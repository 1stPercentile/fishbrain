# G1 pull: the whole wiring

**TLDR.** All 29,474,316 synapses are on disk: `brain/data/synapses.parquet`, plus 13,458,709
segments in `cells.parquet`. The count equals CAVE `synapses_axde` v709 exactly (difference **0**).
Three independent checks agree:
- the spatial index, bitwise on every copy;
- a sample of the relationship index;
- the cells task's counts for the 5 cells it had measured.

The pull was 2.54 GB and took 2 h 29 min on a link that other processes were also using.

## Source: the brain of record
- Prefix: `gs://fish1-public/syn_241003_agg241003_reorient_axde_ei_bayes_idx_pre_250410.precomputed/`
  (HTTPS `https://storage.googleapis.com/fish1-public/<prefix><path>`), public, no login.
- The GCS JSON API listing (`brain/data/raw/listing.json`, read 2026-09-25) shows 29 objects and
  4,361,110,899 bytes. Every download requested `?generation=<listed generation>`, so a
  re-upload can never be mixed in.
- Layer `info`: LINE annotations. Dimensions are 8 x 8 x 30 nm. `lower_bound` is
  (12156, 1797, 306) and `upper_bound` is (270058, 60754, 8673). Properties are
  `pre_synaptic_confidence` f32, `post_synaptic_confidence` f32 and `type` u32. Relationships are
  `pre_synaptic_cell`, `pre_synaptic_site`, `post_synaptic_cell` and `post_synaptic_site`. The two
  `*_site` relationships have no objects in the bucket, and every by_id entry lists 0 of them.

## Strategy: by_id + spatial (2,539,301,126 bytes), justified
| key | files | bytes | holds | pulled |
|---|---:|---:|---|---|
| by_id | 8 | 1,947,525,731 | each annotation once: record + pre cell + post cell | whole |
| spatial0..8 | 12 | 591,769,050 | each annotation's record + id, filed by space | whole |
| pre_synaptic_cell | 4 | 902,418,061 | per pre segment: its annotations | 70-segment sample |
| post_synaptic_cell | 4 | 919,391,712 | per post segment: its annotations | 70-segment sample |
| info | 1 | 6,345 | layer metadata | whole |

- **by_id is the whole wiring by itself.** Each entry is gzip, 65 to 67 bytes compressed and 68
  bytes decoded:
  - the LINE record (p0 xyz, p1 xyz, pre_conf, post_conf, type) = 36 bytes;
  - 4 relationship lists (u32 count, then u64 ids): 1 pre cell, 0 pre sites, 1 post cell and
    0 post sites.

  All 29,474,316 entries had exactly this shape (`k_pre` = 1, `k_post` = 1, `k_site` = 0 on every
  row; 0 anomalies).
- **Spatial is the independent count.** It is 0.59 GB and had to be pulled anyway. It is decoded
  by walking every minishard of every shard, never by computing grid keys, so a wrong key cannot
  hide a chunk.
- **The relationship indexes were sampled, not pulled.** They would add 1.82 GB, about 1.5 to 4 h
  at the measured link rate. by_id already carries the pre and post cells. A byte-range sample of
  the indexes, plus the cells task's relationship-index counts, cross-check them for almost no
  bandwidth.
- **The link set the cost, not the disk** (405 GiB free).
  - At about 16:40 one idle stream ran at 0.69 MB/s, and 16 parallel streams also totalled
    0.72 MB/s.
  - Later, `netstat` on en0 showed 0.28 to 0.31 MB/s total inbound. Other processes on the
    same machine took about half of it.
  - The pull got 0.06 to 0.95 MB/s over time.

## How it was downloaded
- `pull.py download` requests 32 MiB HTTP Range parts, 16 in parallel. Each part resumes from its
  on-disk size.
- A part that delivers under 256 KB in 120 s is dropped and reopened. 91 stalls were caught this
  way, out of 130 retries in total.
- Each file is assembled and checked against the listing's `md5Hash`. A mismatch deletes the file
  and fetches it again. The sha256 is recorded in `brain/data/raw/manifest.json`.
- **Found and fixed during the run:**
  1. `spatial0/0_0_0` is stored with `Content-Encoding: gzip`. Without `Accept-Encoding: gzip`,
     GCS decompresses it on the fly. The range read then returned the wrong 223,379 bytes, and 27
     MD5 mismatches looped until the fix. The fix is to request the stored bytes (MD5 matches) and
     gunzip at decode time.
  2. Single-stream downloads stalled for 8+ min per part. The fix is parallel parts plus stall
     detection.
- The downloader was restarted 3 times: the two fixes above, then 8 to 12 to 16 streams. Resumed
  parts are never refetched. The only bytes fetched twice are the spatial0 loop, about 6 MB.
- Other network reads are not counted in the 2.54 GB: the listing, about 30 segmentation chunks
  for the endpoint check, and 140 relationship-index lookups. Their bytes were not measured.

## What the properties hold (every synapse, by_id)
- **`type`:** 1 = 15,883,209 and 2 = 13,591,107; no other value. **Which one is excitatory is not
  decided here.** The E/I task owns that; see G1-cells.md §8 item 6 for its leads.
- **`post_synaptic_confidence` is empty.** It is 0.0 on all 29,474,316 rows, with 0 NaN. Don't
  use it.
- **`pre_synaptic_confidence` is a signed score in [-1, 1].** 1,760,147 values are exactly 0; there
  are 0 NaN. It tracks `type` but does not decide it:

  | type | pre_conf < 0 | = 0 | > 0 | pre_conf 5/25/50/75/95 pct |
  |---|---:|---:|---:|---|
  | 1 | 12,243,588 | 879,360 | 2,760,261 | -1.0 / -0.943 / -0.637 / -0.0001 / 0.732 |
  | 2 | 2,927,148 | 880,787 | 9,783,172 | -0.881 / 0.0 / 0.400 / 0.869 / 1.0 |

  Histogram (edges -1, -0.99, -0.9, -0.5, 0, 0.5, 0.9, 0.99, 1): 3,139,170 / 2,303,200 /
  4,411,688 / 5,316,678 / 6,778,735 / 3,826,860 / 1,782,651 / 1,915,334.
  ~~Our inference: `pre_conf` is the per-synapse E/I classifier score.~~ **Corrected 2026-09-25 (G1
  neuroscience reviewer, measured):** `pre_conf` is constant within every presynaptic segment
  (7,191,482 of 7,191,482, range < 1e-6), so it is a **per-axon** value, not a per-synapse score. It
  matches the authors' E/I/other classification, which makes it most likely their per-axon Bayesian
  (Dale's-principle) polarity index (inferred). `type` is the per-synapse label.
- **`type` is per synapse, not per cell.** 2,438,936 segments have outputs of both types. That is
  1,262,762 of the 1,532,315 segments with 5 or more outputs. A per-cell sign has to be a choice,
  for example a majority vote, and it goes on the honesty page.
- **syn_id is grouped by type, in four runs:**
  - 0 to 11,797,596: type 1;
  - 11,797,597 to 12,309,386: type 2;
  - 12,309,387 to 16,394,998: type 1;
  - 16,394,999 to 29,474,315: type 2.

  Of the 28,784 blocks of 1,024 ids, only 3 are mixed. **Never subsample by id range**; that
  subsamples by type.
- **Geometry:**
  - p0 range: x 12,156 to 270,057, y 1,797 to 60,753, z 307 to 8,672.
  - Line length p0 to p1: 1st percentile 25.3 nm, median 73.8 nm, 99th 356.4 nm, max 800.0 nm.
  - 6,084 lines have zero length.

## Choices we made (for the honesty page)
1. `synapses.parquet` x, y, z = **p0**, the pre-side endpoint, in voxels of 8 x 8 x 30 nm. It is a
   value from the file, not a derived midpoint. Both endpoints are in `synapses_raw.parquet`.
2. Filters: drop pre == 0, post == 0 and pre == post. Each is counted, and all three removed 0 rows.
3. `cells.parquet` centroids give one vote per synapse. cx, cy, cz is the mean of x, y, z (p0)
   over the segment's outputs and inputs together; the out and in variants use one side only.
   For an input synapse, p0 lies on the partner's side of the cleft, about 74 nm away at the
   median. That is negligible at cell scale.
4. The spatial check counts unique ids, because the boundary duplicates make raw entries overcount.
5. `type` is copied as-is (1 or 2). No sign is assigned in this task.
6. by_id is the source of truth where it and spatial differ. The only difference is the 2 lines
   that spatial dropped.

## Limits and what was not done
- The relationship indexes were checked on 140 segments (7,914 + 33,113 synapse memberships;
  the pre and post samples can overlap), not whole. The 5/5
  exact peer counts, which include both Mauthner candidates, add weight, but it is still a sample.
- The endpoint result rests on 28 synapses.
- The parquet sha256 values depend on the pyarrow version; the content hash does not.
  Determinism was not re-run end to end. A second `parse` would take about 11 min on this machine.
- Memory: the Mac had 13.6 GB of swap in use from other workloads.
  - The first `parse` built the cells table in the same process. It reached a 5.4 GB footprint
    while swapping, and it was stopped.
  - `parse` now frees columns as it goes, and `build_cells` is a separate pass over
    synapses.parquet.
  - Measured peak footprints: parse + cells 4.98 GB, check 5.42 GB. Cells took 524 s because of
    swapping.
- Wall time is a property of this link. Anyone replaying the pull pays 2.54 GB at their own rate.

## Reproduce
From `launches/fishbrain/brain`:
```
.venv/bin/python -m fishbrain.pull list        # listing.json (generations, md5)
.venv/bin/python -m fishbrain.pull download    # 2.54 GB, resumable, md5-verified -> data/raw/
.venv/bin/python -m fishbrain.pull parse       # synapses_raw / synapses / cells parquet + parse_stats.json
.venv/bin/python -m fishbrain.pull check       # integrity.json (spatial, relationship sample, peer counts)
.venv/bin/python -m fishbrain.pull report      # the tables above + content hash + graph shape
```
`pull.py` reuses `fishbrain/precomputed.py` (RECORD, decode_multiple, decode_by_id,
shard_location, get_sharded, BASE) unchanged. Only the local shard reader and the downloader are
new.
